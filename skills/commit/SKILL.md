# Commit

Write single-line conventional commit messages: `<type>(<scope>): <message>`.
Pick the type by effect. A behavior change is never a refactor.

State why the commit was made and what it improves when you have evidence (user input, an issue, a failing test or a reproduced bug). Never make up a why.
Without evidence, state precisely what changed.
Never use vague words like "improve", "update" or "enhance".
Keep the message under 150 characters and never write commit bodies.
