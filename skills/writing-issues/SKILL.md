# Writing Issues

Write a short title in plain words that describes the problem without proposing a change.

Explain the problem and why the issue exists first. Add screenshots or videos when you can upload them.
List confirmed facts an implementer could miss and cannot find in the codebase (e.g. external service settings, production data or decisions made outside the repo). Omit `Watch Out For` if none exist.

Do not write steps or propose a fix. Include only verified facts and mark anything unverified as an open question.
Never reference code or files in git repos directly; put all needed context in the problem or `Watch Out For`.

```md
<problem>

## Watch Out For

- <fact>

> 🤖 **Issue written by <model-name>**
```
